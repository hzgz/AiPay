# AiPay 上线回滚手册

## 一、适用范围

本文档用于 Webman + Art Design Pro 新系统上线后的快速回滚处理。

适用场景：

- 上线后出现大面积登录异常
- 支付创建、回调、补单链路异常
- 管理端或商户端核心页面不可用
- 插件升级、卸载、清理后出现配置错乱
- 关键数据写入异常，继续运行会放大风险

## 二、回滚原则

- 先止血，再恢复
- 先保住支付与资金安全，再处理体验问题
- 任何回滚动作都必须留下操作记录
- 不在故障现场临时发明流程，统一按本文执行

## 三、回滚前准备

上线前必须提前具备：

- 最近一次代码发布包或可回退版本
- 最近一次数据库全量备份
- 支付插件快照目录
- 上传目录、日志目录、审计目录备份
- Nginx / 反向代理可切换配置

如果以上任一项缺失，不应进入正式上线窗口。

## 四、故障分级

### P0 立即回滚

- 支付回调异常，可能造成金额错单
- 签名验签失效，存在伪造风险
- 大面积 500、白屏、无法登录
- 插件清理误删共享数据

### P1 优先回滚

- 商户端核心功能不可用
- 管理端无法处理订单、通道、插件
- 公共入口大范围异常

### P2 视情况修复或局部回滚

- 少量页面文案问题
- 非核心报表异常
- 个别插件管理页异常但主支付链路可用

## 五、标准回滚流程

### 1. 冻结变更

- 立即停止继续发版
- 暂停插件安装、卸载、清理操作
- 暂停非必要后台写操作

### 2. 记录现场

- 记录故障开始时间
- 记录当前版本号
- 记录影响范围
- 导出错误日志、回调日志、操作日志

### 3. 判断回滚层级

按影响面选择：

- 仅前端回滚
- 前后端一起回滚
- 插件单独回滚
- 数据库加代码一起回滚

### 4. 执行回滚

#### 前端回滚

- 回退到上一版静态资源
- 清理前端构建缓存
- 强制刷新 CDN 或反向代理缓存

#### 后端回滚

- 切回上一版 Webman 代码
- 重启 Webman 服务
- 校验 `/api/health`

#### 插件回滚

- 如果只是插件升级故障，优先恢复插件快照
- 恢复插件目录
- 恢复插件声明通道
- 校验插件状态、通道状态、账户绑定状态

#### 数据库回滚

- 仅在确认新写入数据不可兼容时执行
- 先停止写流量
- 恢复最近一次完整备份
- 如有必要，再回放安全的增量日志

## 六、插件专项回滚

支付插件必须支持单独回滚，不应拖累全站。

建议步骤：

1. 停用故障插件
2. 恢复插件目录或快照
3. 恢复插件托管通道
4. 校验插件配置、证书、密钥、回调地址
5. 做一笔小额测试

如果插件已被永久移除，但保留了快照，可按快照恢复流程重建。

## 七、回滚后核验

至少检查以下项目：

- 管理员登录正常
- 商户登录正常
- 支付创建正常
- 支付回调正常
- 订单状态更新正常
- 通道、插件、商户配置可读
- `/api/health` 正常

## 八、回滚后的禁止事项

在根因未确认前，不允许：

- 再次直接上线同一批改动
- 继续清理插件残留
- 手工改库补数据但不留记录
- 跳过小额验证直接恢复大流量

## 九、恢复上线前置条件

只有同时满足以下条件，才允许再次上线：

- 已确认故障根因
- 已补充修复方案
- 已在测试环境复现并验证
- 已完成一次完整回滚演练
- 已完成一次完整支付链路验证

## 十、建议值守

正式上线后建议至少保留：

- 首小时持续观察
- 首日重点监控支付回调、订单状态、登录异常
- 首周每天复核资金和订单趋势

回滚不是失败，而是正式上线流程的一部分。真正危险的是没有回滚方案就直接上线。
