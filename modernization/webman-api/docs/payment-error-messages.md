# 支付错误提示规范

本文档用于收口 AiPay 新系统的支付链路提示语。目标不是照搬旧 TP 版本，而是统一成更适合商用环境的表达方式：简洁、可定位、适合商户理解，同时保留必要的参数指向。

## 设计原则

- 面向商户与接入方输出时，优先说明“哪里错了 + 建议检查什么”。
- 参数类问题尽量带上参数名，例如 `pid`、`type`、`out_trade_no`。
- 平台内部异常不直接暴露底层实现细节，统一收口为稳定文案。
- 上游支付平台返回的明确业务错误可以透传，例如支付宝权限不足、证书无效、网关限流等。
- 同一类错误在 `submit.php`、`mapi.php`、插件回调、通道测试里保持同一说法。

## 错误分组

### 1. 请求参数错误

- 商户编号不能为空，请检查 `pid` 参数
- 缺少支付方式，请检查 `type` 参数
- 缺少必填参数：商户订单号(`out_trade_no`)
- 缺少必填参数：支付金额(`money`)
- 金额格式不正确，请传入有效数字
- 支付金额必须大于 `0`
- 支付金额低于系统最小限额
- 支付金额超过系统最大限额
- 商品名称包含非法字符，请检查 `name` 参数

### 2. 商户与签名错误

- 商户不存在，请确认商户编号是否正确
- 商户账户已冻结，请联系平台管理员
- 签名校验失败，请检查商户密钥与签名参数
- 商户余额不足，请先充值后再发起支付
- 商户套餐未开通，请先联系平台开通
- 商户套餐已过期，请续费后再试

### 3. 通道路由错误

- 当前没有可用的支付插件，请先启用支持网关下单的插件
- 当前商户没有可用的 `[type]` 通道，请先在商户后台启用对应通道
- 当前请求未匹配到可用通道，请检查商户通道配置
- 收款账号不存在
- 收款账号不属于当前商户
- 收款账号与支付方式不匹配
- 收款账号插件与当前请求不匹配
- 收款账号已停用
- 轮询池不存在
- 轮询池已停用
- 轮询池与支付方式不匹配
- 当前轮询池没有可用的 `[type]` 通道

### 4. 订单状态错误

- 商户订单号不能为空，请检查 `out_trade_no` 参数
- 商户订单号重复，请更换后重试
- 订单不存在，请确认订单号是否正确
- 回调缺少商户订单号(`out_trade_no`)
- 订单校验失败，订单标识在落账前发生变化
- 支付流水已被其他订单占用，请联系平台管理员核查

### 5. 插件与上游错误

- 通用易支付V1插件未配置可用通道
- 上游网关地址未配置，请先完善插件接口地址
- 当前上游通道暂不可用，请检查插件配置与状态
- 支付插件`[code]`不支持网关下单
- 支付插件`[code]`未安装
- 支付插件`[code]`已停用

### 6. 系统兜底错误

- 订单已创建，但系统刷新订单状态失败
- 订单网关信息已更新，但系统刷新订单失败
- 支付网关处理失败，请稍后重试

## 旧系统常见提示的收口方式

- `没有该商户` 收口为 `商户不存在，请确认商户编号是否正确`
- `密钥错误` / `sign签名错误` 收口为 `签名校验失败，请检查商户密钥与签名参数`
- `没有这个通道` 收口为 `当前商户没有可用的[type]通道，请先在商户后台启用对应通道`
- `订单号重复` 收口为 `商户订单号重复，请更换后重试`

## 不建议直接透传的内容

- PHP 报错、SQL 报错、文件路径、类名、堆栈信息
- `未定义索引`、`Trying to access array offset` 这类开发期异常
- 插件内部调试 memo、迁移中提示、兼容层说明

## 可以透传的上游错误

- 支付平台权限不足
- 证书不正确
- AppID / 商户号不匹配
- 上游订单状态明确失败且文案可直接帮助定位

上游文案若明显含旧系统品牌、乱码或无效链接，应在插件层做二次整理后再返回。
