# 支付插件与通道治理规范

## 一、目标

支付插件必须成为通道的唯一归属源，不再允许“插件一套、通道目录再手工维护一套”的重复模式。

目标是做到：

- 所有支付插件统一放在 `plugins/payments/<plugin_code>/`
- 每个插件自带自己的通道声明、安装、修复、卸载、清理和恢复逻辑
- 后台只展示统一的支付插件管理视图，不再把插件通道和共享业务通道混成两套入口
- 不需要某个插件时，可以整包停用、卸载、清理，并尽量做到无残留

## 二、目录规范

每个支付插件使用独立目录：

```text
plugins/
  payments/
    <plugin_code>/
      plugin.json
      runtime/
      assets/
      migrations/
      snapshots/
```

约束：

- `plugin_code` 全局唯一
- 一个目录只对应一个插件
- 插件运行文件、静态资源、快照、迁移脚本都收口在本插件目录或插件命名空间下
- 任何跨插件共享能力都必须走平台公共服务层，不能反向写死到别的插件目录

## 三、通道归属原则

新系统里，插件拥有自己的通道定义权。

这意味着：

- 通道不是单独再维护一套“来源不明”的目录
- 后台看到的通道，应当能追溯到所属插件
- 插件停用或卸载时，必须能准确找到它创建过的通道记录

当前采用的归属合同：

- 插件在 `plugin.json` 中声明 `managed_channels`
- 每个插件通道编码必须以前缀 `<plugin_code>_` 开头
- 写入共享通道表时，标记为插件创建来源
- 平台通过编码前缀和插件声明共同识别归属关系

示例：

```json
{
  "managed_channels": [
    {
      "code": "wechat_app_qr",
      "name": "微信软件挂机",
      "type": "wxpay",
      "info": "插件内置通道模板",
      "status": 1,
      "sort": 0,
      "maxcount": 10
    }
  ]
}
```

## 四、生命周期行为

### 1. 安装

- 自动写入插件声明的缺失通道
- 自动恢复插件名下已回收的声明通道
- 同步展示字段、排序、状态等基础信息

### 2. 修复

- 检查插件目录、声明通道、命名空间表、运行时文件是否漂移
- 对缺失项执行补齐
- 对明显脏数据给出审计结果

### 3. 升级

- 保留既有插件归属
- 同步新的通道声明
- 对需要迁移的字段执行升级脚本

### 4. 停用

- 只关闭插件可用状态
- 不直接删除通道和快照
- 保留后续恢复入口

### 5. 卸载

- 先做依赖审计
- 明确告诉操作者：会影响哪些通道、表、文件、快照
- 允许先卸载、后清理

### 6. 清理

- 清理插件目录
- 清理插件命名空间数据表
- 清理插件拥有的通道记录
- 清理完成后保留审计结果

### 7. 快照恢复

- 插件卸载或清理后，允许通过快照恢复
- 恢复时要同时恢复插件声明通道
- 共享表中的插件通道恢复必须单独处理，不能遗漏

## 五、后台展示原则

后台应当遵守以下展示规则：

- 支付插件是统一入口
- 通道信息作为插件详情或插件附属数据展示
- 插件拥有的通道可以在平台总览中被看到，但不应再被误认为“独立于插件存在”
- 对于插件托管通道，后台共享目录应弱化直接编辑和直接删除

建议最终产品形态：

- 左侧是支付方式
- 右侧是该支付方式下的插件列表
- 选中插件后，展示插件表单、插件状态、插件能力、插件托管通道
- 未选择支付方式和插件前，不展示无意义表单

## 六、卸载与清理边界

为了避免误删，系统必须遵守以下边界：

- 绝不猜测不带插件前缀的共享通道归属
- 只清理由插件声明或插件前缀可以明确识别的记录
- 如果插件通道仍被账户、订单、轮询池、授权关系引用，则阻止清理
- 清理失败时必须明确告诉操作者阻断原因

## 七、无残留目标

所谓“无残留”不是无条件强删，而是：

- 对可安全清理的数据做到完整清理
- 对不可清理的数据给出明确阻断项
- 对清理动作保留日志、审计和快照

理想结果包括：

- 插件目录被移除
- 插件命名空间表被移除或清空
- 插件托管通道被移除
- 插件运行时残留被清除
- 审计台账记录 `removed_managed_channel_count`

## 八、运维命令

永久移除某个支付插件时，统一使用：

```bash
php tools/remove_payment_plugin.php <plugin_code>
```

如需保留恢复快照：

```bash
php tools/remove_payment_plugin.php <plugin_code> --keep-snapshots
```

## 九、上线前检查

- 核对每个插件目录都存在 `plugin.json`
- 核对 `managed_channels` 编码前缀是否正确
- 核对后台展示是否只保留统一的支付插件入口
- 核对插件停用、卸载、清理、恢复快照流程
- 核对插件通道被引用时，系统是否能正确阻止误删

## 十、结论

新系统的正确方向不是“插件一套、通道目录再单独一套”，而是：

- 插件目录统一
- 插件生命周期统一
- 插件通道归属统一
- 清理与恢复统一

这样后台结构才不会重复，维护成本才会下降，后续新增微信、QQ、支付宝、USDT 等软件插件时，也能真正做到独立、可控、可回滚。
