# AiPay生产上线检查清单

本文档用于 Webman + Art Design Pro 改造后的生产收口。目标不是“能访问”，而是“可正式上线、可回滚、可维护、可审计”。

## 一、当前基础状态

- 管理端、商户端、公共入口已经切到 Webman API + 新前端体系。
- 管理端和商户端已统一为 Art Design Pro 风格。
- 主要后台菜单、公共页、公告页、导航页已完成中文化与乱码修复。
- 支付插件已收口到 `plugins/payments/<plugin_code>/` 目录规范。

## 二、上线前必须完成

### 1. 域名与网络

- 为管理端、商户端、前台入口分别配置正式域名。
- 全站启用 HTTPS，并检查证书自动续期。
- 校准支付回调地址、异步通知地址、同步跳转地址。
- 校准跨域、反向代理、真实 IP、上传大小限制。

### 2. 账号与安全

- 修改默认管理员口令，禁用弱口令。
- 复核管理员、商户测试账号，删除无效测试账号。
- Google 验证若暂时关闭，需要明确补回时间点和责任人。
- 检查登录失败限制、IP 风控、操作日志、敏感操作确认是否生效。
- 生产环境 `APP_DEBUG`、详细报错、开发调试入口必须关闭。

### 3. 支付插件

- 仅保留真实需要的支付插件目录，移除测试或演示插件。
- 每个插件单独核对：
  - 上游商户号、密钥、证书、回调白名单
  - 订单创建、查询、回调、补单、退款能力
  - 安装、禁用、卸载、清理、恢复快照流程
- 旧易支付兼容插件已移除，不再回归到旧目录。
- 插件移除建议使用：

```bash
php tools/remove_payment_plugin.php <plugin_code>
```

如需保留恢复快照，追加：

```bash
php tools/remove_payment_plugin.php <plugin_code> --keep-snapshots
```

### 4. 内容与界面

- 复核所有菜单标题、按钮、表格列名、弹窗标题是否仍有英文或演示文案。
- 复核公告管理、导航管理、主题模板、风控中心、财务审计、订单中心等关键页。
- 清理前台默认导航、默认公告、测试站点名、演示说明文案。
- 确认空状态、404、无权限、加载失败提示均为正式中文。

### 5. 通知与外部能力

- 配置正式 SMTP、短信、站内信模板。
- 配置对象存储或附件目录策略。
- 校准定时任务、队列、回调重试、日志切割。
- 配置监控告警：服务存活、错误率、回调失败率、数据库容量。

### 6. 数据与回滚

- 完成上线前数据库备份。
- 明确代码回滚和数据库回滚方案。
- 确认支付插件快照目录、审计目录、日志目录备份策略。
- 预演一次“支付插件卸载并恢复快照”的真实回滚链路。

## 三、建议的正式上线验收

### 管理端

- 登录、退出、权限菜单、角色分配正常。
- 商户、订单、公告、导航、主题、支付配置、系统设置核心流程可用。
- 所有关键写操作有日志或审计留痕。

### 商户端

- 登录、首页概览、订单查询、余额/资金日志、充值、工单、资料、安全设置正常。
- 风格统一，无 TP 遗留视觉页面跳出。

### 前台与兼容入口

- `/` 统一入口正常。
- 前台首页、公告列表、公告详情、缺失页提示正常。
- 对外展示的站点名、标题、页脚、导航为正式内容。

### 支付链路

- 发起支付、回调验签、订单入账、补单、异常日志链路全部跑通。
- 至少做一次真实支付沙箱或小额实单验证。

## 四、建议的上线后观察期

- 首日重点盯登录失败、支付回调失败、订单状态不一致、页面 JS 报错。
- 首周每天核对资金类报表与订单量趋势。
- 新增插件或启用兼容插件前，先做独立冒烟与回滚演练。
